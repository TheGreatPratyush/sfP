## 3. Discovered Issues & Root Causes

### Issue 1: `/admin` Route 404
- **Root Cause:** The `client/src/App.jsx` React router configuration only explicitly defined `/admin/login` and `/dashboard` (among others). When the Owner navigated directly to `/admin`, the React router fell through to the `*` catch-all route and redirected them to the storefront home page `/`.
- **Minimal Fix:** I injected a strict `<Route path="/admin" element={<Navigate to="/dashboard" replace />} />` into the router. This securely funnels the request to the dashboard route, which properly invokes the `<ProtectedRoute>` logic to redirect unauthenticated Owners to the login screen.

### Issue 2: Collection Links Routing to "All Products"
- **Root Cause:** The main storefront navigation header (`StoreHeader.jsx`) contained hardcoded static placeholder links (e.g., `/collections/new-arrivals`). However, the existing Neon UAT database only contained randomly named migration test categories (`Men`, `Women Clothing`, `Test Cat...`). Because the URL slugs from the hardcoded links did not match any real database category IDs, the `Collection.jsx` component gracefully failed and redirected the user back to the default `Shop` view (All Products).
- **Minimal Fix:** Instead of modifying database test data or rewriting the collection logic, I replaced the 4 static links with a dynamic map over the `categories` array using the existing `useCatalog` hook. Now, the header dynamically mirrors the actual categories present in the remote Neon database.
